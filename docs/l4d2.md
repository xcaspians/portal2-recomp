# Left 4 Dead 2 (experimental, Mac first, offline only)

The same pipeline recompiles **Left 4 Dead 2** (Steam app 550) from its own
Linux build (depot 554, i386, the engine branch Portal 2 grew from). It is
experimental: see "Status" below for how far it gets.

**Local and offline only.** A recompiled build must never meet Valve's online
servers or VAC. Every launch gets `-insecure +sv_lan 1 -nomaster`
(`launch_args` in `tools/games.py`, appended by `games.forced_args` whatever
arguments `run_game.py`, `make_app.py` or `build_ios.py` were given). Play
single-player campaigns with bots, which are a local listen server. Never
`connect` to an internet server.

You must own Left 4 Dead 2 on Steam. Nothing from Valve is in this
repository: the game is built on your Mac from your own copy.

## Inputs

| What | Where |
|---|---|
| Game content | the Mac install, `steamapps/common/Left 4 Dead 2` (Steam) |
| Linux binaries | depot 554: `download_depot 550 554` in the Steam console |
| `libstdc++.so.6`, `libgcc_s.so.1` (i386) | the Debian packages `setup.sh --game mel` downloads (`system_lib_dir`) |
| `libsteam_api.dylib` | Steamworks.NET 20.1.0, as for Portal 2 |

`config/local.json`, under `games.l4d2`: `game_root`, `linux_root` (the
depot), `system_lib_dir`, `steam_api_dylib`, `steam_appid` 550, `depot_id`
554, `user_dir`.

## Build and run (by hand for now)

```sh
python3 tools/gameprep.py --game l4d2          # 2 s: build/l4d2/prep
python3 tools/build_game.py --game l4d2 --release
python3 tools/run_game.py --game l4d2 --show -- -game left4dead2 -novid -windowed -w 1280 -h 720
python3 tools/run_game.py --game l4d2 --show -- -game left4dead2 -novid +map c1m1_hotel
```

`setup.sh` doesn't offer L4D2 yet.

## What differs from Portal 2

- Program `hl2_linux`, a fixed-address executable (`ET_EXEC`, like Mel's).
- Modules in `bin/` and `left4dead2/bin/`; the dedicated-server copies
  (`*_srv.so`), Chromium (`libcef.so`, `chromehtml.so`) and `shaderapidx9.so`
  are left out: `shaderapivk.so` renders through the runtime's Direct3D 9
  bridge, as for Portal 2 (`libtogl.so` stays: the launcher links it).
- `libstdc++` and `libgcc_s` are linked dynamically, as in Mel.
- Interfaces: `VEngineClient013` and `VFileSystem018` where Portal 2 has 015
  and 017. Only the iOS menu's engine calls name them.
- Valve's coroutines (`Coroutine_*` in `libvstdlib.so`, used by
  `matchmaking.so`) run in the runtime (`runtime/coroutine.c`, profile
  `host_exports`): vstdlib's own version copies stacks and longjmps into
  frames lifted code can't express.
- Steam: Portal 2's SDK 1.53a interfaces plus Timeline V001 (ignored) and a
  longer `SteamGameServer014` (slots past 42 answer 0). `P2_STEAM_OFFLINE=1`
  (profile `steam_offline`) refuses server lists, pings and lobbies, and the
  old Steam socket API answers "none": nothing reaches Valve's servers.

## Status (25 November 2026, round 12)

Mac, `--release`, M-series Mac mini:

- **Main menu:** reached (the Bink menu background plays), about 150 fps.
- **`+map c1m1_hotel`, offline:** the map loads, the client joins the local
  listen server, the Director's script starts and places the wandering
  infected ("Initiating Reserved Wanderers"). About **120 fps** with the
  window focused (`+engine_no_focus_sleep 0` for a hidden test window;
  unfocused, the engine sleeps 50 ms a frame), memory footprint **2.0 GB**.
  Ran 4 minutes without a trap.
- **Not seen yet:** survivor bots and a horde. Both need a player in the
  game: an unattended run stays at the intro, so `director_force_panic_event`
  has nothing to act on. That's the first thing to try with a keyboard.
- Roots found so far: 2 (`config/l4d2-roots.json`, `tools/discover_game.py
  --game l4d2 --release --jobs 2`).

Next: play the first map by hand (bots, a horde, saves), then iOS (its own
app, a touch layout with shove, reload, item slots and flashlight, the 4 GB
memory guard).
